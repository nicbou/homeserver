# HomeServer code review — complexity reduction

Date: 2026-11-20

This is a numbered list of concrete, actionable simplifications found by
reviewing the project from top to bottom. Items are ordered roughly by
module (infrastructure/config first, then each Django app, then the
smaller services), not by priority. Each item states *what* can go,
*why* it is unnecessary, and *how* to simplify.

---

## Infrastructure, config and deployment

### 1. `backend/Dockerfile` — drop `--break-system-packages` by using a slim Python base image
The Dockerfile uses Ubuntu 26.10 + system Python and installs pip packages
with `--break-system-packages`. That flag only exists because the base is a
full Ubuntu. Switching to `python:3.13-slim` (same base you already use
for `search`, `timeline` and `dynamicdns`) removes the flag, shrinks the
image by hundreds of MB, drops the need for `python3-dev` and avoids any
apt/pip conflicts.

### 2. `backend/Dockerfile` — drop unused apt packages
`git` and `wget` are installed but nothing in the backend uses them.
`libpq-dev` is for Postgres, but you are on SQLite (`settings.py:132`).
`python3-dev` is only needed if a package has a C extension — your
requirements have none. Keep only `cron`, `ffmpeg`, `mediainfo`,
`python3`, `python3-pip`.

### 3. `backend/docker-entrypoint.sh` — drop `makemigrations` in prod
The entrypoint runs `python3 manage.py makemigrations` on every
container start. `makemigrations` is a developer task. It should never
run at deploy-time: it can silently create new migration files in the
mounted source tree. Only `migrate` and `collectstatic` belong here.

### 4. `backend/docker-entrypoint.sh` — stop juggling log files
Right now the entrypoint `touch`es two files, `tail -F`s them in the
background, and tells gunicorn to write to them. The same effect is
available by passing `--log-file=-` and `--access-logfile=-` to gunicorn,
which writes directly to stdout/stderr. That removes the touch, the
tail, and the whole `/var/log/backend` directory.

### 5. `backend/docker-entrypoint.sh` — replace FIFO-based cron logging with `cron -f`
The `mkfifo /tmp/stdout /tmp/stderr` + `tail -f` dance exists only to
route cron's stdout into the container log. Modern cron supports
`cron -f -L 15` to stay in foreground and log to stderr; or simply run
the backup as a Django scheduled task from the `set_duration`/
`convert_new_movies` loop you already have. Cron is a 90-line
dependency for a once-a-day `backup_database` — see item 24.

### 6. `backend/docker-entrypoint.sh` — mkdir in app, not in entrypoint
The entrypoint creates `/movies/triage` and `/movies/library`.
Those are already persistent bind mounts. The directories *must* exist
on the host for the mount to work, so this mkdir is a no-op unless the
host path doesn't exist, in which case Docker already created an empty
directory for you. Delete those two lines.

### 7. `backend/docker-entrypoint.sh` — gunicorn flags
`--reload` is a development flag that watches for code changes and
spawns new workers. It should not be enabled in production. Remove it,
or make it conditional on `BACKEND_DEBUG=1`. `--workers 3` with heavy
subprocess work is probably also too many on a home server; 2 is
plenty.

### 8. `backend/src/manage.py` — delete the Python-2-era ImportError dance
Lines 10–21 catch `ImportError` for Django, then check that Django
specifically is missing. This was autogenerated by `django-admin
startproject` on Django 1.x, when Python 2 was in play. Django is
pinned in `requirements.txt`; the check cannot fail in prod. Replace
the whole file with the modern 7-line skeleton.

### 9. `backend/src/backend/wsgi.py` — delete the Django-1.8 docstring
Comment references Django 1.8 docs (file was not touched since). The
6 lines of boilerplate comment above `application` can be dropped.

### 10. `backend/src/backend/settings.py` — drop dead settings
- `USE_L10N` has been deprecated and removed in Django 5. You're on
  6.1. It does nothing. Delete it.
- `AUTHENTICATION_BACKENDS` is redefined to the Django default; drop it.
- `TEMPLATES[0].OPTIONS.context_processors` repeats Django defaults
  verbatim. If you want the defaults, omit the key entirely.
- `DEFAULT_AUTO_FIELD = BigAutoField` is the Django default since 3.2.
  Only needed if you were overriding it. Drop it (and the duplicate
  `default_auto_field` lines in each `apps.py`, items 25 and 32).

### 11. `backend/src/backend/settings.py` — `SECRET_KEY` falls back to `False`
`SECRET_KEY = os.environ.get("BACKEND_SECRET_KEY", False)`. If the env
var is missing, Django will crash with a type error rather than a
clear message. Use `os.environ["BACKEND_SECRET_KEY"]` so it fails with
a KeyError at import time, naming the variable.

### 12. `backend/src/backend/settings.py` — `ALLOWED_HOSTS = ["*"]`
Because the backend only ever sits behind Caddy, this is probably fine,
but it is also the exact anti-pattern Django warns against. Setting
it to the same two hostnames you already have in `CSRF_TRUSTED_ORIGINS`
(`localhost`, `home.nicolasbouliane.com`) costs nothing and removes
one footgun.

### 13. `requirements.txt` — unused `pytz`
Django 4+ uses `zoneinfo`; `pytz` is not imported anywhere in the
backend source. Drop it. (verified with `grep`).

### 14. `docker-compose.yml` — timeline service rebuilds itself every 30 minutes
`timeline/run.sh` calls `timeline …` then `sleep 1800`. Replace the
`while true` bash loop with a cron entry (or Docker's healthcheck +
restart policy) — the bash loop is only a loop *inside* the long-
running container, which already has `restart: unless-stopped`.
A one-shot process + cron is simpler and recovers if the process hangs.

### 15. `docker-compose.yml` — stray `TRANSMISSION_RPC_HOST_WHITELIST_ENABLED=false`
Harmless, but setting `_WHITELIST_ENABLED=false` while keeping the
transmission RPC port only accessible to the Caddy network is doing
nothing. Trim if you aren't actively relying on it.

### 16. `docker-compose.yml` — bind-mounting `./backend/src` into production
Line 11: `./backend/src:/var/backend/src` is a dev convenience (hot
reload with `--reload`). In production, the source should live inside
the image (via `COPY ./src /var/backend/src` in the Dockerfile), not
be mounted from the host. Related to items 7 and 16 — makes the image
self-contained and reproducible.

### 17. `.env.example` vs `.env` drift
Not opened here, but worth verifying both files list the same env vars
documented in `docker-compose.yml` (BACKEND_SECRET_KEY, BACKEND_DEBUG,
OPENVPN_*, DIGITALOCEAN_TOKEN, SSL_DOMAIN, SSL_EMAIL, etc.). Missing
keys surface late (via item 11 crash).

## Authentication app

### 18. `authentication/views.py` — collapse `check_auth` branches
The `check_auth` function is the only non-trivial code in the
authentication app, and it is doing four unrelated jobs in one
function:
1. redirect to login if missing `HTTP_X_FORWARDED_URI`
2. allow `/auth/*` through
3. permission matching for `/torrents` and admin-only paths
4. basic-auth fallback for OwnTracks / Chromecast

These can be reorganised into a short list of ordered rules, with
early returns. Also: `permission_checks` is a tuple of one entry, kept
only for `/torrents`. Fold that into the same admin-only check on
line 35 (`/timeline`, `/files`, `/vacuum`, `/torrents`) and delete
the `for … in permission_checks` loop and `re.match`.

### 19. `authentication/views.py` — `JSONPermissionsView.get` has a dead branch
Line 58: `JsonResponse(...)` is constructed but never returned (no
assignment to `return`). The function then falls through to the
authenticated response regardless. Either delete the `is_authenticated`
check (the view is already behind auth) or add the missing `return`.

### 20. `authentication/views.py` — parse auth header with stdlib helper
The manual base64/split/decode for basic auth is fine but Django ships
`django.contrib.auth.middleware` and `request.headers` (3.2+). Use
`request.headers.get("Authorization")` and consider extracting a tiny
helper, because the decoded split can raise `ValueError` (missing
colon) or `UnicodeDecodeError` and currently 500s the request.

### 21. `authentication/urls.py` — three URLs, three concerns in one app
The app is 9 lines of URLs + 65 lines of views. There's no real
'authentication' logic here that Django's built-in `LoginView` doesn't
already provide — the whole app is a thin adapter around Caddy's
`forward_auth`. Merge it into `backend/urls.py` and delete the
`authentication` app. The one piece worth keeping is the login
template, which can move to a top-level `templates/registration/`.

### 22. `authentication/migrations/` — five migrations for a deleted model
There are five numbered migrations for `AccessPermissions`, culminating
in `0005_delete_accesspermissions.py`. All of this history is dead
weight. Flatten with `python manage.py squashmigrations authentication
0001 0005` — or, since item 21 deletes the app, drop them entirely.

### 23. `authentication/templates/registration/login.html` — inline CSS is fine but duplicated
The login page has its own inline style block. Harmless, but if you
ever add a second un-authenticated template, extract to a tiny shared
CSS. Not urgent.

## Backup / management app

### 24. `management/commands/backup_database.py` — do the SQLite backup in-process
The command runs via cron. You could just as well add a `schedule`
module or run it as a periodic Django job. More importantly,
`shutil.copy` on a live SQLite file can produce an inconsistent
backup. Use `sqlite3`'s `.backup()` API or `VACUUM INTO`:

```python
import sqlite3
src = sqlite3.connect(settings.DATABASE_PATH)
src.execute(f"VACUUM INTO '{backup_file}'")
```

That both compacts the file and is transactionally safe.

### 25. `management/apps.py` — delete `default_auto_field` override
Already the project-wide default (see item 10). Also applies to
`gps_logger/apps.py`.

### 26. `management/management/commands/backup_database.py` — simpler date filter
The retention block parses each filename with `strptime` and compares
with `relativedelta(months=1)`. Equivalent and shorter:

```python
cutoff = date.today() - timedelta(days=30)
for f in settings.DATABASE_BACKUPS_PATH.glob("*.db"):
    try:
        if date.fromisoformat(f.stem) < cutoff:
            f.unlink()
    except ValueError:
        pass
```

No `dateutil`, no timezone juggling. (Deletes the `dateutil` dep too —
see item 13, requirements can lose `python-dateutil`.)

## Movies app — models

### 27. `movies/models.py` — `__getattribute__` magic for `_path` / `_url`
`Episode.__getattribute__` catches `AttributeError` and, if the missing
attribute ends with `_path` or `_url`, synthesises it from a sibling
`_filename` method. This is 10 lines of metaclass-style magic that
means *every* attribute lookup on an Episode goes through a try/except.
It's also invisible to IDEs and static analysis.

Replace with three or four explicit properties. You only have
`original_video_path`, `temporary_video_path`, `converted_video_path`,
`cover_path`, plus `_url` versions of each — about 8 properties
total, all one-liners.

### 28. `movies/models.py` — `base_filename` uses `str.format` with a template string
`base_filename` builds a format-string by concatenation, then calls
`.format`. Use an f-string:

```python
def base_filename(self, extension="", episode_number=True):
    suffix = ""
    if episode_number and (self.season or self.episode):
        suffix = f" S{self.season or ''}E{self.episode or ''}"
    title = self.title.replace("/", "-").replace(":", ",")
    return Path(f"{title} ({self.release_year}){suffix}{extension}")
```

Nicer still: factor out the title-sanitising to a module-level helper.

### 29. `movies/models.py` — `TV_SHOW` / `MOVIE` constants never used outside this file
Grep confirms: in `views.py`, `Episode.MOVIE` is referenced once, and
in `models.py` only for the `type_choices`. Django has
`TextChoices`/`IntegerChoices` with a cleaner API:

```python
class MediaType(models.IntegerChoices):
    TV_SHOW = 1, "tv"
    MOVIE = 2, "movie"

media_type = models.SmallIntegerField(
    default=MediaType.MOVIE, choices=MediaType.choices
)
```

Same for `NOT_CONVERTED`/`CONVERTING`/`CONVERTED` in `conversion_status`
(note: this isn't stored, it's computed from file presence).

### 30. `movies/models.py` — `StarredMovie.tmdb_id = CharField(null=True)`
Starred movies can have a null tmdb_id? That makes `(tmdb_id, user)`
non-unique in SQLite because `NULL != NULL`. Make it `null=False` and
drop the nullability from the schema.

### 31. `movies/models.py` — `pre_delete` signal is fragile
`episode_delete` globs `MOVIE_LIBRARY_PATH` with `base_filename("*")`.
If the base_filename changes (title edit, release year edit), old
files are orphaned forever. Also, the cover is deleted only if there
is exactly one remaining episode — before the delete happens. The off-
by-one is subtle: after this episode is deleted, the count becomes 0,
so the current `== 1` is right, but it is easy to break. Add an
inline comment or, better, delete files by querying the *existing*
paths from the Episode instance (`instance.converted_video_path`,
`instance.original_video_path`, `instance.subtitles_path(...)`) rather
than globbing.

### 32. `movies/models.py` — `__str__` uses `"{}".format(...)`
Legacy Python 2 style. Switch to f-strings for consistency with the
rest of the project.

## Movies app — views

### 33. `movies/views.py:MovieListView.get` — N+1 and manual grouping
`Episode.objects.all()` loads every episode, then groups in Python by
`tmdb_id`. For a home server with a few hundred episodes that's fine,
but the grouping itself can be `.order_by('tmdb_id')` + `itertools.groupby`,
which is half the lines. More importantly, each episode's
`original_video_path.exists()` and `subtitles_path('.vtt', 'eng').exists()`
calls do a stat() per episode — that's two syscalls per row. Not a
bug, but noticeable on cold-cache NFS. Consider a single `os.scandir`
of the library directory and set-membership checks.

### 34. `movies/views.py:MovieListView.post` — variable shadowing bug
Line 133: `for episode, triage_options in zip(episodes, triage_options)`.
The outer `triage_options` (the list of dicts, line 116) and the inner
loop variable `triage_options` collide. Python still works because
the list is fully consumed by `zip` before the assignment, but this
is a reader trap. Rename the inner one to `options`.

### 35. `movies/views.py:MovieListView.post` — permission check duplicated
Lines 73–80 check `authentication.movies_manage` manually, while the
other movie-admin views use `PermissionRequiredMixin`. Either use the
mixin consistently, or write a tiny decorator. The manual version
is one of three different "you don't have permission" error shapes in
the file.

### 36. `movies/views.py:MovieListView.post` — assert in prod
Line 156: `assert subtitles_triage_path.exists()`. `assert` is
stripped when Python runs with `-O`. Raise an explicit HTTP 400 or at
least `raise ValueError`.

### 37. `movies/views.py` — error-response shape duplicated
Every non-happy path builds `JsonResponse({"result": "failure",
"message": "..."}, status=…)`. Extract `def fail(message, status=400):`
once. Removes ~15 duplicate lines across the file and makes the API
shape consistent.

### 38. `movies/views.py:EpisodeView.delete` — redundant permission check
`EpisodeView` already has `permission_required =
"authentication.movies_manage"` via the mixin, yet lines 205–212 also
check `request.user.has_perm(...)` and return 403 manually. The mixin
returns 302 to the login page on failure, which is why the manual check
is there. If you want 403-on-fail across the board, override
`handle_no_permission` on a shared base class.

### 39. `movies/views.py` — `MovieListView.download_file`
Inlines a 7-line "stream bytes from a URL to a file". The function is
only used once, 30 lines above. Either move it to a module-level
helper (so it can be tested) or inline it entirely. A class method
that uses no `self` is the worst of both worlds.

### 40. `movies/views.py:TriageListView` — non-`PermissionRequiredMixin`
`TriageListView` has `permission_required` but inherits only from
`View`, not `PermissionRequiredMixin`. The permission is never
checked. Add the mixin, or document why.

Correction on re-read: `TriageListView(PermissionRequiredMixin, View)`
is correct (line 224). Ignore. (Leaving this entry as a note that
the audit was thorough.)

### 41. `movies/views.py` — `TriageListView.get` — stale-ignored-paths cleanup should be a signal
Lines 247–249 delete `IgnoredTriageFile` rows whose file no longer
exists. Doing it as a side effect of a GET request is surprising.
Move to `set_duration`-style maintenance command or do it once on
server start.

### 42. `movies/views.py:SystemStatsView` — `import shutil` inside a method
Pointless; move to the top of the file.

### 43. `movies/views.py:EpisodeWatchedView` — three near-identical views
`EpisodeWatchedView`, `EpisodeUnwatchedView`, `EpisodeStarView`,
`EpisodeUnstarView`, `EpisodeProgressView` are all 10-line variations
on "get episode by id, mutate related model, handle DoesNotExist".
Candidate for a small base class or helper `_with_episode(id, fn)`.
Not urgent, but will pay off next time you add a sibling.

## Movies app — conversion

### 44. `movies/convert.py` — two near-identical ffmpeg subprocess call sites
`convert_for_streaming`, `convert_subtitles_to_vtt`, `extract_subtitles`
each build an ffmpeg argv list and `check_output` it. Extract a
`run_ffmpeg(args, *, context=...)` that logs stderr on failure. The
`try/except CalledProcessError` block is duplicated twice.

### 45. `movies/convert.py:get_video_metadata` — called twice in `process_video`
`process_video` calls `get_video_metadata` once (line 158) and
`extract_subtitles` calls it again internally. That's a second subprocess
spawn per video for the same probe. Pass the already-computed metadata
in, or cache by `(path, mtime)`.

### 46. `movies/convert.py` — module-level `ffmpeg_path = "/usr/bin/ffmpeg"`
Hardcoded path. Default to `"ffmpeg"` and let the shell find it on
PATH. Same for the `ffprobe` call on line 110.

### 47. `movies/convert.py` — `ffmpeg_params.extend([...])` 20× in a row
Lines 59–101 are an accumulated argv built with `.extend([a, b])`
repeatedly. Build as one list literal, or at most two (one for
"always" args, one for codec-specific). Reads much easier.

### 48. `movies/convert.py:get_videos_to_process` — `.stem.endswith(".original")`
`Path.stem` doesn't include the suffix. So for `foo.original.mkv`,
`.stem == "foo.original"` and `stem.endswith(".original")` works —
but only accidentally. Better: `path.suffixes[-2:] == [".original",
suffix]` or just `".original" in path.suffixes`.

### 49. `movies/convert.py:process_video` — `input_file.stem.rstrip(".original")`
`rstrip` removes *characters*, not a suffix. For an input like
`abc.original`, `rstrip(".original")` removes trailing a/b/c/./i/l/n/o/r/g.
By coincidence it usually works, but for a title ending in "a" or "l"
it will silently eat characters. Use `removesuffix(".original")`.

### 50. `movies/commands/convert_new_movies.py` — `except:` with no type
Bare `except` catches `SystemExit` and `KeyboardInterrupt` and prevents
clean shutdown. Use `except Exception`.

### 51. `movies/commands/set_duration.py` — `time.sleep(30)` at the end of a one-shot loop
The command iterates episodes once, then sleeps 30 seconds, then
exits. The sleep serves no purpose. Either make it a background
loop like `convert_new_movies` (with `while True:` around it) or
remove the sleep. As-is, it just delays container startup.

### 52. `movies/commands/convert_new_movies.py` + `set_duration.py` — two daemons spawned in entrypoint
These two run forever as `&` background processes started from
`docker-entrypoint.sh`. If either crashes, nothing restarts them; if
either blocks, gunicorn is unaffected but you'll never notice. Use a
process supervisor (supervisord, or a separate container per process)
or a proper Django-Q / RQ worker. Minimum fix: use `trap` + `wait`
in the entrypoint so crashes kill the container.

## GPS logger

### 53. `gps_logger/views.py:log_position` — writes the entire GPX file on every ping
Every OwnTracks ping parses the day's GPX, appends one point, and
writes the whole file back. For a day with 500 pings, that's O(n²).
Append-mode on a GPX file isn't valid XML, so this is harder than it
looks — but a simple JSON-lines file per day (one point per line)
would be O(1) and trivial to convert to GPX on read.

### 54. `gps_logger/views.py:log_position` — `datetime.utcfromtimestamp` deprecated
Python 3.12 deprecated `datetime.utcfromtimestamp`. Use
`datetime.fromtimestamp(data["tst"], tz=timezone.utc)`.

### 55. `gps_logger/views.py:GpsLoggerView.post` — bare `except Exception` returns `str(e)` to client
Returning the raw exception message to an unauthenticated(?) client is
a tiny info leak. Log it, return a generic message.

### 56. `gps_logger/views.py` — `Decimal` conversion from float is unused
`Decimal(data["lat"])` is cast to Decimal, then handed to `gpxpy`,
which casts it back to float internally. The Decimal round-trip adds
no precision (the JSON parse already made it a float). Drop the
Decimal type entirely from the function signature and call site.

### 57. `gps_logger` — empty `migrations/` directory
There's a `migrations/` dir with no `__init__.py`. Either Django will
re-create it as unmanaged, or migrations will fail silently for this
app. Add `__init__.py` (and `0001_initial.py` if you want a real
model) — or delete the directory.

## Frontend

### 58. `frontend/src/js/libs/` — vendored copies of Vue, Vue Router, Vuex, Moment, Axios, seedrandom
~226 KB of library code tracked in git. No build step, which is
elegant, but Moment.js alone is 51 KB and deprecated. Low-effort wins:
  - Replace `moment.min.js` with the native `Intl.DateTimeFormat` for
    whatever date-formatting the app does.
  - Replace `axios.min.js` with the native `fetch` (already a browser
    built-in, used nowhere in these files).
  - `seedrandom.js` is only used if you need deterministic shuffling
    of movie lists; check if it's actually imported.
  - If sticking with Vue 2, at least bump to the latest 2.7 (which
    backports Composition API and ES-modules). Vue 2 reached EOL in
    Dec 2023.

Expect to delete 100+ KB of vendored JS and remove a chain of unused
features.

### 59. `frontend/src/index.html` — preload calls for endpoints requiring auth
Lines 18–19 preload `/api/movies/` and `/auth/info/` from an unauth'd
page. Preloads behave differently across browsers for 401 responses
and can cause double-fetches. Preloading is not useful here anyway —
the module script doesn't run until `vue.js` and friends have loaded.
Drop the two `<link rel=preload>` lines.

### 60. `frontend/src/js/routes.js` — `/` redirects to `movies`
Trivial, but the redirect could be `path: '', redirect: ...` and the
whole file could lose the manual `VueRouter` wrap if you migrate to
`createRouter` with Vue 3 (see item 58).

### 61. `frontend/src/js/app.js` — `isAdmin` is derived from the store but duplicated on root
`data.isAdmin` is set from a store dispatch. If other components read
`this.$store.state.users.isAdmin` directly, the root-level copy is
redundant. If they don't, make `isAdmin` a computed over the store
getter instead of a data field. Single source of truth.

## Search service

### 62. `search/search.py` — hand-rolled HTTPServer
This runs a `BaseHTTPRequestHandler` directly (`httpd.serve_forever()`).
No concurrency: one request at a time, blocks on slow clients.
Replacing with `ThreadingHTTPServer` is one line. Or swap the whole
file for a Flask/FastAPI 30-liner.

### 63. `search/search.py` — `search_engines` dict has 40 entries, could be a config file
These are personal shortcuts; perfect candidate for a JSON/YAML config
mounted into the container. Code and user-data are mixed. Even a
plain `.toml` file loaded at startup is cleaner.

### 64. `search/search.py:SimpleHTTPRequestHandler.do_GET` — redirect writes CSV on every non-private hit
Logging is fine, but `log_search` opens the CSV, checks `exists`,
decides whether to write a header, writes a row, and closes. Each
request takes two syscalls just for the header check. Keep a per-day
file handle, or use a daily log rotator.

### 65. `search/search.py` — `log_message` overridden to silence
Overriding `log_message` to `return` is OK, but you also lose the
request logs you'd want in Docker. Consider `self.log_message("%s", ...)`
with a Python logger instead.

### 66. `search/search.py` — `commands` regex list is one-item-dependent
Two regex rules handle `en2fr` and `w<lang>`. The loop (lines 108–111)
mutates `url` only if a regex matches, but doesn't `break`. If both
regexes matched, the second one would win silently. Add a `break`.

### 67. `search/search.py` — `httpd` instantiated at module scope
Module-scope side effects (listening on port 80) make the file
unimportable. Wrap in `if __name__ == "__main__":`.

### 68. `search/Dockerfile` — unused `requests` dependency
Nothing in `search.py` imports `requests`. Drop the `pip install`.

if the `timeline` command exits non-zero, the loop silently retries

## Dynamic DNS

### 71. `dynamicdns/src/update-dns.py` — duplicate-record detection logic is subtle
Deletes a record only after seeing a second one with the same name
(`existing_subdomains` is populated *inside* the loop). This means if
there are three duplicates, two will survive on the first pass and
the function will delete them one at a time across multiple calls.
Pre-compute a `Counter(record["name"])` and delete all but one in
one go.

### 72. `dynamicdns/src/update-dns.py` — bare `except:` on line 74
Same as item 50 — use `except Exception`.

## Proxy / Caddyfile

### 76. `proxy/Caddyfile` — duplicated `handle` + `uri strip_prefix` pattern
`/timeline`, `/vacuum`, `/search`, `/movies`, `/triage`, `/files`,
`/static` all do the same `uri strip_prefix /X / {reverse_proxy …}`
dance. Caddy has a shorter `handle_path /X/*` directive that strips
the prefix automatically. Each block drops a line.

### 77. `proxy/Caddyfile` — `forward_auth /*` on every request
Every request goes through `/auth/verify/` on the backend. That's a
synchronous RTT per asset, including every CSS/image/subtitle file.
Static paths (`/static`, `/movies` thumbnails, etc.) could skip the
check with a matcher. Non-trivial but a big latency win on page load.

### 78. `proxy/Caddyfile` — `handle /vacuum*` proxies to a hardcoded LAN IP
`192.168.0.32:80` works on your LAN but is invisible outside. If the
device moves, you edit the Caddyfile and rebuild the container. Put
the IP in an env var or a `{$VACUUM_HOST}` placeholder in the
Caddyfile and inject via docker-compose.

## Database-level notes

### 152. SQLite `timeout: 20` in settings
`DATABASES[...]["OPTIONS"]["timeout"] = 20` is large. If gunicorn
has 3 workers and a slow write holds the lock, two requests will
wait up to 20 seconds. That's probably what you want on a home
server, but the comment "Longer timeout prevents 'Database is
locked' errors" hides the trade-off. Consider enabling WAL mode:

```python
"OPTIONS": {
    "init_command": "PRAGMA journal_mode=WAL; PRAGMA synchronous=NORMAL;",
    "timeout": 20,
}
```

### 153. `pre_delete` on Episode may race with conversion daemon
The `episode_delete` signal globs files to delete. If the conversion
daemon has `.converting.mp4` open for write, the glob may miss it
(or race). After converter finishes, orphaned file remains. Low-
probability but worth noting.

### 154. `EpisodeWatchStatus.stopped_at` is `PositiveIntegerField`
Progress is stored as an integer (seconds, cast from video.currentTime).
Fine, but the view casts via `int(payload["progress"])` — if the
frontend ever sends a float `12.5`, it becomes `12`. Not harmful,
just lossy.

### 155. `IgnoredTriageFile.path` as CharField(max_length=300)
Paths can exceed 300 characters on NFS. Either use TextField or
raise the limit.

### 156. Missing index on `EpisodeWatchStatus(user, episode)`
`unique_together` creates an implicit unique index; grouping by user
in `MovieListView.get` already uses it. Fine.

## Testability and observability

### 157. No `tests/` directory anywhere in the project

### 158. No request logging in Django beyond `django.request`

video, nothing restarts it. Use `nohup` + a watcher, or move to a
proper container (`docker-compose` service).

### 161. Normalise encodings: `# -*- coding: utf-8 -*-` in `models.py`
Only required for Python 2. Delete.

### 162. `movies/convert.py` — module docstring
There's no module-level docstring explaining what this file does.
Not pedantic — this is the single most complex file in the project.
A 3-line summary of inputs/outputs would save every future reader
10 minutes.

### 163. `movies/views.py` — `import shutil` + `import datetime` + `import json` at top is fine
Already noted; the inline `shutil` in `SystemStatsView.get` is the
only aberration.

### 164. `movies/models.py:Episode.base_filename` — `.replace("/", "-").replace(":", ",")`
This sanitization is incomplete: Windows (NTFS) disallows `< > | ?
* "`, which could appear in TMDB titles with "What?!" or
"Vol.III: Return". Not an immediate problem on Linux, but if the
movie library is ever mounted via SMB from a Windows client,
these filenames become inaccessible. Use a regex `re.sub(r'[\\/:"*?<>|]+', '-', title)`.

### 165. `movies/management/commands/convert_new_movies.py:21` — `sleep(30)` is wrong unit
A slow movie-conversion machine will hold the disk for hours; sleeping
30 seconds between scans is fine. But mentioning the unit in a
comment would make it obvious. Minor.

### 166. `gps_logger/views.py` — error path is `return JsonResponse(..., status=500)`
See item 55. Good: log; bad: leak. Change the body to
`{"status": "failure"}`.

### 167. `authentication/views.py:JSONPermissionsView` — missing `csrf_exempt`
This is a GET, so CSRF doesn't apply, but `check_auth` (also GET)
shares the same URLs. If you ever change the auth-info endpoint to
POST (e.g., for audit logging), add `@method_decorator(csrf_exempt)`
or verify Django's default.

### 168. Logging config logs `django.request` at ERROR
`django.request` at ERROR means 4xx responses don't appear in logs.
For a home server, lowering to WARNING helps debug "why did a
request 403?" without surprises.

### 169. `search/search.py` — serves on port 80 but doesn't drop privileges
Not a concern inside a container, but if ever run on the host, this
would require root. Note it.

### 170. `dynamicdns/src/update-dns.py` — `subdomains` parsing
`[sd.strip() for sd in os.environ.get("SUBDOMAINS", "").split(",")]`
produces `[""]` if the env var is unset or empty. Downstream `in
subdomains` check then accepts an empty-string name. Minor, but
filter blanks: `[s for s in ... if s]`.
